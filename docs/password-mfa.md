# Парольная и многофакторная аутентификация

## Парольная аутентификация

В основе лежит проверка знания секрета: пользователь вводит логин и пароль,
приложение хеширует введённый пароль с солью и сравнивает его с сохранённым
значением. Для защиты от перебора применяются медленные алгоритмы хеширования
— Argon2, bcrypt, PBKDF2.

Основные уязвимости парольных схем:

- перехват данных при отсутствии шифрования канала;
- отсутствие управления сессиями;
- повторное использование паролей между сервисами — утечка базы одного
  сервиса компрометирует аккаунты на других (атаки типа *credential
  stuffing*).

## Многофакторная аутентификация (MFA)

| Фактор | Надёжность | Типичная атака |
|---|---|---|
| SMS / Email OTP | Низкая | SIM-swapping, перехват SS7 |
| TOTP (RFC 6238) | Средняя | Real-time phishing proxy |
| Push-уведомления | Средняя/высокая | MFA fatigue (push-бомбардировка) |
| Аппаратный ключ / passkey | Высокая | Кража устройства |

По данным NIST, MFA и переход к архитектуре нулевого доверия (Zero Trust)
остаются основными методологическими ориентирами при отказе от парольных
политик как единственного фактора защиты.

!!! warning "MFA fatigue (push-бомбардировка)"
    Злоумышленник, уже владеющий паролем жертвы, отправляет десятки
    push-запросов на подтверждение входа подряд, рассчитывая, что пользователь
    подтвердит один из них по ошибке или просто чтобы остановить поток
    уведомлений. С 2024 года многие провайдеры используют *number matching* —
    пользователь должен ввести на устройстве число, показанное на экране
    входа, что делает случайное подтверждение невозможным.
