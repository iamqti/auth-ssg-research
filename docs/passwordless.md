# Беспарольная аутентификация

Беспарольная аутентификация строится на асимметричных ключах и стандартах
FIDO2/WebAuthn. При регистрации аутентификатор (аппаратный ключ или
встроенный чип биометрии) генерирует пару ключей: публичный уходит на
сервер, приватный остаётся в защищённом хранилище устройства (TPM, Secure
Enclave).

При входе сервер присылает случайное задание (challenge), устройство
подписывает его приватным ключом, сервер проверяет подпись публичным
ключом.

## Origin-binding — защита от фишинга «по построению»

Ключевое свойство WebAuthn — привязка к источнику: аутентификатор не
подпишет запрос, если домен в адресной строке браузера не совпадает с тем,
на котором ключ был создан. Это делает классический фишинг (поддельная
копия сайта на похожем домене) технически бессмысленным — в отличие от
TOTP-кодов, которые пользователь может ввести на фишинговой странице.

## Passkeys

Passkeys — синхронизируемое расширение FIDO2: ключи, доступные с нескольких
устройств пользователя (Apple iCloud Keychain, Google Password Manager).
Технически это те же ключи FIDO, но с удобством автоматической
синхронизации — решается проблема «потерял единственный аппаратный ключ».

Остаточные риски беспарольных схем: кража самого устройства с включённой
биометрией, атаки на цепочку поставок ПО/прошивки аутентификатора, усталость
пользователя при частых push-подтверждениях.
